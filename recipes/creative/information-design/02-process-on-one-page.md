# Process on one page

Use this when a service, workflow, or technical mechanism feels complicated and a viewer needs to understand what happens from start to finish.

## The idea

Turn the journey into a small number of meaningful stages. Show what enters the process, what changes at each stage, where a handoff occurs, and what the viewer receives at the end. The page should answer “what happens next?” without pretending that every exception belongs in the main graphic.

## Borrowable shape

**Starting point → three to five stages → important handoffs or decision points → visible output → next action.**

Give each stage a verb-led title and one short explanation. Use arrows for sequence, branches only for real decisions, and a small legend when a line, color, or icon has a necessary meaning. Keep supporting detail in a linked note, caption, or separate page.

## Tiny illustrative example

**From a service request to an installed result**

`Request a site visit → confirm the requirements → prepare the proposal → complete the installation → hand over care details`

Under the flow, a small note says: **The exact stages and handoffs should match the actual service.**

## Adapt

Show the real stages and handoffs when explaining an actual service. If the mechanism is the selling point, replace generic labels with the meaningful transformation: “collect signals,” “match the right option,” or “assemble the result.” If the process has too many branches, show the common path and link to the exceptions. Do not imply a step, turnaround, or deliverable that the organization has not established.
