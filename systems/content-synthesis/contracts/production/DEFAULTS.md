# Content Production Defaults

- Confirm the source Insight/Opportunity when one materially matters, audience, objective, platform/medium, desired action, proof requirements, and current PlatformProfile before production. Do not require lifecycle objects merely to begin creating useful content.
- Use the best available creation method for the requested result. The active model/harness/user chooses actual tools, Skills, renderers, providers, and execution approach from the real host environment; AURA does not run capability preflight or provider resolution. Missing optional tooling never lowers the content standard.
- Produce the actual requested medium when the host can do so. If the host genuinely cannot render/record/export the requested medium, do not pretend it did. When useful to the user, produce the strongest production-ready source package the available tools can support—containing the same substantive audience content plus sufficient direction for later rendering—and state the remaining real execution limitation truthfully. A summary, outline, keyword checklist, or description of future work is not the deliverable.
- A production-ready source package should be genuinely usable: complete content/script, medium-native units and sequence, media/visual/audio instructions, timing or dimensions where relevant, technical/render requirements, resolvable source/proof pointers, CTA/next step, packaging/metadata, and acceptance criteria appropriate to the format. Do not cite an internal standard, benchmark, dataset, or public source unless it exists in loaded/captured evidence.
- Preserve a claim-auditable surface for customer-facing output. Text-native artifacts are scanned directly. Opaque/rendered media should save a compact JSON claim-surface sidecar when that materially improves later verification and reference it from the canonical Asset as `extensions.businessos.claim_surface_ref`; record audience-visible text, spoken text, and material visual claims, or a substantive reason that none exist. This is provenance/QA data, not customer-facing copy and not a substitute for inspecting the render.
- Inspect the actual audience-facing artifact when one exists, not only its supporting metadata. Check continuity from promise through proof and action, verify opaque-media claim-surface parity when relevant, and remove internal contract, Run, qualification, or implementation language from the deliverable.
- Final QA checks factual meaning and claims, Brand, editorial quality, originality, accessibility/usability, platform integrity, and the actual rendered output or production-ready source package. Record concrete findings/corrections against the exact Asset version rather than asserting that QA occurred.

## Medium-specific native floor

- Article deliverables contain finished reader-facing copy at the depth needed to fulfill the reader task and brief. Do not pad or truncate the work to satisfy an arbitrary word count; a concise article may be correct when it fully serves the requested outcome, while a complex topic may require substantially more depth.
- Audio/podcast source packages include the episode premise and listener promise, audience/listening context, title, complete spoken script or genuinely sufficient host notes, segment timing appropriate to the planned episode, transitions/audio cues, evidence/source/pronunciation notes, CTA, edit direction, and show notes/platform packaging. Claimed duration must be internally consistent with the actual script, timecodes, and cues. A text source package states future recording/mastering targets; it does not claim that audio was already recorded, mixed, mastered, rendered, or exported.
- Presentation source packages include the audience/setting/objective and delivery context, an actual slide-by-slide narrative sized to the job, substantive visible copy/data, per-slide visual direction, speaker notes or asynchronous narration where applicable, source/proof attribution, CTA/decision close, and presentation-level QA. Use as many slides as the audience journey requires rather than targeting an arbitrary slide count; a list of proposed slide topics is only an outline.
- Video/animation/demo source packages include the complete audience message plus scene/shot/state sequence, visuals, audio/narration, timing, transitions/interactions, platform specifications, and edit/render notes appropriate to the requested duration and format.
- Image/carousel/infographic source packages include final copy/data plus frame/canvas sequence, layout hierarchy, visual direction, dimensions/safe areas where relevant, accessibility text, source attribution, and export instructions.
