# AURA Core

Core owns AURA's organization-owned foundation: canonical organizational context, evidence and provenance, durable decisions/results/unresolved work, measurement and Learning, reusable operating knowledge, business-scoped customization, workspace resolution, reference integrity, and strict organization isolation.

Core does **not** own the active model's semantic understanding of the user's request, reasoning, planning, provider/tool selection, live capability discovery, permissions, orchestration, delegation, concurrency, retries, scheduling, or execution. Those belong to the active model/harness and the real systems it can access.

AURA playbooks are reusable operational knowledge, not executable authority. Provider-neutral capability declarations may describe what a playbook benefits from, but the active harness decides how or whether those capabilities are satisfied.

Canonical AURA product source remains protected during ordinary organizational work. Organization-owned state may adapt through explicit context/preferences, evidence-supported Learning, and business-local operating knowledge without turning a local success into a universal rule or creating a hard dependency on Git, MCP, a hosted service, a scheduler, a proprietary crawler, Obsidian, or any specific model/provider.

Canonical JSON state remains authoritative even when Core generates human-readable Markdown views from it.

The Core invariant is: **preserve organizational meaning and reusable operating knowledge; let the capable intelligence/runtime decide how best to work.**
