# AURA Core

Core owns AURA's organization-owned foundation: canonical organizational context, evidence and provenance, durable decisions/results/unresolved work, measurement and Learning, reusable operating knowledge, organization-scoped customization, workspace resolution, reference integrity, and strict organization isolation.

Core does **not** own the active model's semantic understanding of the user's request, reasoning, planning, tool/provider selection, permissions, orchestration, delegation, concurrency, retries, scheduling, or execution. Those belong to the active model/harness and the real systems it can access.

AURA operating knowledge uses **Playbook → Workflow → Step**. Playbooks are end-to-end business jobs; Workflows are reusable procedures; Steps are minimum useful guidance. They describe what good work requires in natural language rather than defining a tool inventory or execution authority.

The active model may use AURA operating knowledge, another installed Skill, both, or another sound method. AURA does not define a universal capability vocabulary and does not prevent the model from using a better tool/resource/method discovered at runtime.

Canonical AURA product source remains protected during ordinary organizational work. Organization-owned state may adapt through explicit context/preferences, evidence-supported Learning, and local Workflow knowledge without turning one local success into a universal rule or creating a hard dependency on Git, MCP, a hosted service, a scheduler, a proprietary crawler, Obsidian, or any specific model/provider.

Canonical JSON state remains authoritative even when Core generates human-readable Markdown views from it.

The Core invariant is: **preserve organizational meaning and reusable operating knowledge; let capable intelligence and its runtime decide how best to work.**
