# Module Independence

Business OS modules may run inside the full suite or as standalone distributions with Core.

- Only installed modules may own or execute domain contracts in the current installation.
- Intelligence from an uninstalled optional module is an enrichment, not a hidden hard dependency. Use current Business Context, supplied source material, existing canonical objects, direct Observations, or bounded task-specific research sufficient to complete the active job.
- Do not create canonical Insights or Opportunities on behalf of an uninstalled semantic owner. If foreign-domain interpretation is necessary for continuity, keep it provisional in the active job and preserve the underlying SourceRecord/Observation so the proper module can reinterpret it later if installed.
- Missing optional modules must never cause required practitioner steps to disappear. They change the evidence path or executor, not the business outcome or quality bar.
- If a requested task is primarily owned by an uninstalled module, report that the module is not installed rather than silently claiming its domain.
- When a module is later added, consume existing compatible Core objects and business state instead of reinitializing or duplicating them.
