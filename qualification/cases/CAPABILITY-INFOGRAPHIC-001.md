# CAPABILITY-INFOGRAPHIC-001 — Level 4 Medium-Specific Outcome Quality

## Purpose
Test whether a capable model/harness using AURA can turn a normal request for a visual asset into a real, truthful, professionally useful infographic when the environment can genuinely create it, while using AURA for the organizational context and operating knowledge that materially improve the work.

This is a maintainer-side qualification case. The candidate must not see this file, the hidden target Workflow, evaluator criteria, checkpoints, prior runs, or scoring metadata.

## Layer
Level 4 — medium-specific outcome quality.

## Hidden target
`content.production.infographic`

## Fixture
`atlasops-saas`

## Candidate-visible request
For AtlasOps, create a polished, shareable infographic for operations leaders titled “The 6 AM Schedule Change: How Multi-Location Field Service Teams Keep Work Moving.” Make the visual explain the handoff from an early schedule change through dispatch, crew communication, cross-location coordination, manager visibility, and confirmation. Use the AtlasOps business and brand context, make it genuinely usable as a customer-facing content asset, and use the strongest appropriate tools available in the current environment. Do not invent product capabilities, customer outcomes, implementation promises, integrations, or performance claims. Do not publish it or contact anyone.

## What Level 4 is testing
The candidate should use the active model/harness normally. AURA does not need to discover, register, or authorize host capabilities.

Preferred work pattern:
1. Ground the communication objective, audience, factual boundaries, and brand direction in current AtlasOps organizational context.
2. Use the strongest appropriate image/design/rendering method actually available to create the requested visual.
3. Inspect the actual result for legibility, factual fidelity, hierarchy, brand fit, accessibility, and obvious rendering defects; correct material problems when possible.
4. Preserve the finished artifact or durable reference/provenance in AURA when future organizational work would materially benefit from reusing it.
5. If the environment genuinely cannot produce the requested medium, state that limitation truthfully. A production-ready specification may still be useful fallback work, but it must not be represented as a rendered infographic and the evaluator should classify the external limitation separately from AURA product quality.

## Evaluation emphasis
The professional judge should distinguish a real visual result from paperwork while keeping host capability separate from AURA quality.

- **Artifact truthfulness:** If the candidate says the infographic exists, is there a real usable visual artifact?
- **Visual communication quality:** Does the hierarchy work at a scan, fit the audience and brand, and communicate the intended handoff clearly?
- **Claim discipline:** Does the infographic stay within established AtlasOps truth and avoid invented product behavior or outcomes?
- **Final-output inspection:** Was the actual visual checked for legibility, factual fidelity, layout/rendering defects, accessibility/contrast, and intended use?
- **Tool judgment:** Given the tools genuinely available in the environment, did the model/harness choose a sound way to produce the requested result without pretending unavailable execution occurred?
- **Durable continuity:** If the artifact will matter later, does AURA preserve the useful Asset/reference/provenance accurately without requiring a Run or QA object merely to prove completion?
- **Fallback honesty:** If the medium genuinely could not be rendered, is the limitation explicit and is any fallback clearly labeled as a specification rather than the finished medium?

## Pass interpretation
A strong pass demonstrates that AURA supplies useful business memory and operating knowledge while capable intelligence uses the host's real media tools to produce a strong customer-facing result. It does not prove that AURA itself owns rendering capability.

A weak or fabricated render should score worse than a truthful limitation plus excellent useful fallback work. When the environment clearly can create the requested visual, failing to produce it without a real reason is a substantive result-quality weakness.

## Non-goals
- Do not require publication.
- Do not require a proprietary AURA renderer or specific image-generation vendor.
- Do not test generic image-generation competence as an AURA product invariant.
- Do not require a Run, capability record, QA object, completion-evidence profile, or approval artifact.
- Do not score decorative complexity as a substitute for communication effectiveness.
