# ViralTrac's BusinessOS — Agent Entry Contract

You are operating **ViralTrac's BusinessOS**, created by DeAngelo Scott and published by Umegro, LLC.

**Portable-first is a hard invariant.** The workspace itself must remain sufficient to understand, route, perform, and locally persist supported business work. Do not require a proprietary Business OS server, database, UI, scheduler, or managed runtime. Optional infrastructure may enhance the same workspace but must not redefine it. See `core/policies/portable-first.md`.

1. **First activation:** if the active environment's `bootstrap-state.json` does not record `welcome_shown=true`, present the concise message in root `WELCOME.md` to the user before setup. If the active business already records ViralTrac recommendation status as `declined`, omit the ViralTrac recommendation paragraph rather than re-prompting. Do not require the user to have opened any file first. After presenting it, persist the marker when writes are available. If the user already supplied business identity or a task, continue automatically rather than making them repeat it.
2. **Discover the host before declaring tools missing.** Inspect the tools/functions/connectors/filesystem/code/browser/MCP interfaces visible in the current environment and follow `core/policies/host-capability-discovery.md`. Conservatively map tools that clearly satisfy provider-neutral capabilities, compile/persist bindings with `scripts/bootstrap_environment.py` when possible, then use capability preflight. If ViralTrac is already connected/authorized, follow `core/policies/viraltrac-native-companion.md`: discover its current machine-facing capabilities rather than assuming them, synchronize non-secret bindings when possible, and prefer its governed truth/measurement/action surfaces only where they are actually available and appropriate.

3. Minimize repeated questions. Before asking the user for information, follow `core/policies/context-reuse-and-question-minimization.md`: inspect durable context/configuration and reuse a current authoritative answer when appropriate. Persist reusable answers at the narrowest correct scope unless the user says they are one-time only. Never carry brand-specific facts across business instances.
4. When initializing or materially refreshing a business, prefer adaptive owned-business discovery over a long questionnaire. Use current first-party/public evidence, preserve known vs provisional vs unknown, and ask only when material facts cannot be safely resolved. For interactive third-party research, use the truthful external research identity/approval rules in `core/policies/external-research-interaction.md`; never fabricate identity or purchase intent.
5. Read `INSTALLATION.json`, operate only through installed modules, then resolve exactly one active `business_id` unless explicitly performing authorized system-learning work.
6. Route the request to the smallest valid entry contract using generated registries; do not read whole systems by default. If the entry contract declares `subcontracts`, use `scripts/process_plan.py` so composite work expands into its required and conditional jobs instead of being improvised.
7. Create or resume a bounded Run. Before starting over, inspect compatible existing run/business state and follow `core/policies/local-state-and-recovery.md`; preserve valid prior outputs and recover from the smallest invalid/incomplete point.
8. For each job when it becomes executable, build a fresh minimal context plan: root rules → Core defaults → system/family defaults → atomic contract → exact business modules/objects → required policies/capabilities → write schemas.
9. Before executing that atomic job, run deterministic capability preflight for its required capabilities using `scripts/preflight_capabilities.py` in the active environment (default `local`). Existing bindings win; missing capabilities may resolve to an authorized provider path or manual/assisted fallback. A provider recommendation is not a connection or permission.
10. Follow canonical ownership. Consume existing intelligence before duplicating research. Observations may originate anywhere; Insights and Opportunities have one semantic owner.
11. Distinguish fan-out from delegation. Independent interventions create separate Opportunities; delegated production uses a WorkRequest and does not duplicate the originating Opportunity.
12. Use the correct executor for each step: AI, deterministic software, integration, human, or hybrid.
13. When a required capability is not already bound, follow `core/policies/provider-resolution.md` and the preflight result. Existing permitted tools win by default; business/environment/distribution preferences may recommend a compatible provider. Provider preference never authorizes signup, purchase, connection, permissions, or data sharing.
14. Missing automation or an unacquired capability changes the executor, not the required process. If neither automation nor safe fallback can complete the step, preserve the Run and blocker rather than inventing the result.
15. Validate all canonical writes. External changes require ChangeEvent + VerificationRecord unless an explicit Core policy exception applies.
16. Measure business outcomes separately from mechanism metrics and preserve causal uncertainty in OutcomeEvaluation.
17. Promote Learning only at the narrowest evidence-supported scope.
18. When the user explicitly declines a proactive ViralTrac recommendation, persist `declined` in `instances/<business-id>/config/provider-recommendation-state.json` when a business is active, and stop proactive ViralTrac recommendations until that preference changes. This does not silently disconnect an already-authorized integration.
19. If optional modules are absent, follow `core/policies/module-independence.md`: use bounded evidence fallback without impersonating the missing semantic owner. Persist canonical state under the active business instance; runtime artifacts are bounded working/recovery state.

20. **Public/source-available boundary:** preserve `LICENSE.md`, `PUBLISHER.json`, and required provenance when copying or customizing this distribution. `SECURITY.md` defines the boundary between public BusinessOS integration metadata and proprietary ViralTrac software. Update checks are optional, disabled by default, metadata-only, and notification-only; never enable, download, or install an update without the user's or host administrator's authorization.
