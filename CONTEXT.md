# ViralTrac AURA — Agent Entry Contract

You are operating **ViralTrac AURA (Agentic Understanding and Reinforcement Architecture)**, an AI-native BusinessOS created by DeAngelo Scott and published by Umegro, LLC. Follow `BRANDING.md` for public naming. Stable technical compatibility identifiers such as `businessos`, `BUSINESSOS_*`, existing contract IDs, and object conventions remain valid.

**Portable-first is a hard invariant.** The workspace itself must remain sufficient to understand, route, perform, and locally persist supported business work. Do not require a proprietary AURA/BusinessOS server, database, UI, scheduler, or managed runtime. Optional infrastructure and trusted local capability packs may enhance the same workspace but must not redefine it. See `core/policies/portable-first.md`.

**Before the first business write in every fresh agent session, follow `core/policies/agent-execution.md` and `core/policies/operating-scope.md`.** Contract IDs are identifiers for playbooks/services, not executable paths. Canonical Business Context is schema-valid JSON state, not arbitrary Markdown. Follow `core/policies/active-business-truth.md`: preserve explicit/sourced/provisional/unknown truth boundaries across **all** business-facing outputs, never fabricate missing business facts, and never equate unknown/not-found with absent. Use `core/policies/resource-aware-execution.md` to reach reliable outcomes with minimum sufficient work rather than exhaustive-by-default research or orchestration. Resolve customization through `core/policies/preferences-and-adaptation.md` and shared-session behavior through `core/policies/shared-workspace-coordination.md`; AURA does not become a harness merely because a harness may use subagents or parallel workers. During ordinary business work, AURA product files are protected infrastructure: do not create/patch replacement scripts, contracts, schemas, tests, or system files to work around a failed operation.

For an ordinary organization/business request against an already initialized business, prefer `python3 scripts/enter.py "<the user's complete original request>"` as the deterministic front door. It establishes the workspace/business, route, bounded Run, Run-scoped work directory, process/context plans, capability preflight, and lightweight monitoring-continuity visibility, then hands execution back to the active model/harness. The full resolved envelope is persisted inside the Run while the ordinary CLI returns a compact sufficient handoff; use its `execution_envelope_ref` or `--full` only when deeper inspection is needed. It is not an agent, scheduler, model router, or replacement harness. Fresh-business initialization and AURA product-development requests continue through their dedicated paths below.

1. **First activation:** if the active environment's `bootstrap-state.json` does not record `welcome_shown=true`, present the concise message in root `WELCOME.md` to the user before setup. If the active business already records ViralTrac recommendation status as `declined`, omit the ViralTrac recommendation paragraph rather than re-prompting. If a needed capability is still missing and a trusted optional local capability pack can satisfy it, inspect the pack before concluding the capability is unavailable; bind a healthy existing tool without reinstalling it. Installing, upgrading, or repairing system software requires explicit authorization and a fixed product-owned recipe—never search for and run an arbitrary installer. If ViralTrac is already connected/authorized, follow `core/policies/viraltrac-native-companion.md`: discover its current machine-facing capabilities rather than assuming them, synchronize non-secret bindings when possible, and prefer its governed truth/measurement/action surfaces only where they are actually available and appropriate.

## Agent execution quick path
- For ordinary organizational work on an initialized business, enter with `python3 scripts/enter.py "<the user's complete original natural-language request>" [--business-id <id>]`. Treat its route/process/context/capability/Run resolution as authoritative unless relevant state changes or a returned high-level interface reports a real unresolved need; do not rerun or inspect the lower-level planning/preflight helpers. Begin from its exact `inputs` and material context refs, use the returned `scripts/persist_run_results.py` interface for AI-authored declared canonical results, and use the Run `work_dir` for scratch/build/cache/render state. The complete durable envelope is available through `execution_envelope_ref` or `--full`; do not rediscover information it already resolved. Treat `monitoring_continuity` as a lightweight memory cue: do not derail unrelated work, and do not call planned cadence scheduled without a verified binding.
- Use `python3 scripts/route_and_resolve.py "<natural-language request>" --business-id <business-id> --show` when debugging/recovering the lower-level routing path or when a governed flow explicitly calls for route resolution without opening a new envelope.
- If you already know a contract ID, resolve/read it with `python3 scripts/resolve_contract.py <contract-id> --show`; do not try to execute the ID.
- After setup, continue the unresolved original outcome. “What should we do next?” must end in a prioritized recommendation or bounded evidence plan, not a menu of systems.
- Conversational bootstrap should ground structured facts with one or more `bootstrap_explicit_context.py --source-file <path>` / `--source-text "<verbatim statement>"` inputs; use `--preference-profile-file` for reusable preferences that must apply to the first downstream Run; pass unresolved original intent with `--residual-request "<remaining request>"` (or `--initialization-only` only when setup was the whole request). Treat the returned residual route as a required continuation before final response. Unsupported inferred classifications must not enter canonical truth.

Customer-facing is based on intended use, not publication state; an unpublished outward draft remains governed, and work generated during the current execution may not be relabeled imported/preexisting. Ambiguous or semantic evidence must remain unresolved rather than being selected merely to complete the Run.
