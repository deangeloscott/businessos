# Adding a Contract

Create a separate contract when work is independently routable/reusable, needs materially different context/capabilities/risk, creates a distinct canonical output, or has its own fallback/verification logic. Keep trivial mechanical substeps inside the parent contract or deterministic utility.

Use stable namespaced IDs. Declare the smallest required reads/writes and generic capabilities. The Process is an ordered SOP with executor tags. Add routing decisions, measurement, and Learning only when meaningful. Run registry generation and validation after authoring.
