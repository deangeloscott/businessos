# Measurement & Learning

`MetricDefinition` says what a metric means. `MetricObservation` says what was measured. `VerificationRecord` says whether an intended change happened. `OutcomeEvaluation` says what happened afterward and how confidently an intervention contributed. These are intentionally separate meanings, not mandatory lifecycle stages.

Outcome Evaluation may preserve baseline, evaluation window, expected/observed effects, attribution method, confounders, guardrails, conclusion, and causal confidence when those details materially improve future interpretation. Shared outcomes should not be duplicated merely because several domains contributed.

## Learning scope

Learning belongs to one organization.

- **Domain Learning** — reusable guidance whose meaning belongs to one AURA domain inside the active organization.
- **Business Learning** — reusable guidance that genuinely applies across the active organization.

Use the narrowest scope the evidence supports. Maturity may move among `hypothesis`, `experimental`, `emerging`, `validated`, and `standard`; status may become `contradicted`, `deprecated`, or `superseded`. These are evidence/applicability descriptions, not execution authority.

AURA does not automatically pool private Learning across organizations. When a reusable method should cross organization boundaries, use an explicit sharing/adoption mechanism such as an InnovationPackage/ProcessExtension, or make it deliberate canonical AURA product-development work. This keeps client/organization memory isolated while still allowing proven methods to be shared intentionally.
